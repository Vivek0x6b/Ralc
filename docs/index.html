RALC: Relational Context Allocation

A language model only knows the text you send it. When a chat gets long, you can't send all of it, so you have to pick. RALC picks the messages that belong together, so the model gets the whole story inside a small token budget.

Why the difference?

Two messages about the same thing look alike, so ordinary selection treats them as duplicates and keeps only one. RALC knows they are connected (one replaced the other), so it keeps both.

How it works

From a long chat to a small, connected context

RALC sits between your program and the model. It never rewrites the question and never touches the model's answer. Its only job is choosing which past messages to include.

  1. Store every message

    Each message becomes a point in a graph, saved in a local SQLite file.

  2. Connect the messages

    An extractor reads each message for names and decisions, and RALC draws links between messages.

    The free built-in extractor uses simple patterns. Gemma 4 can do this job instead and understands things a pattern can't, like one decision replacing another.

  3. Find starting points

    When a question arrives, a small embedding model on your machine finds the messages most similar to it.

  4. Follow the links

    From those starting points, RALC walks the links to related messages, even ones that share no words with the question.

  5. Rank the candidates

    Each candidate gets a score combining similarity to the question, how strongly it's linked, shared names, and how recent it is.

  6. Fill the budget

    RALC adds the best messages until the token budget is used. It skips near-duplicates, but not linked messages, since those complete each other. It stops early when nothing useful is left, so it can use fewer tokens than allowed.

  7. Hand off

    The chosen messages come back in conversation order. You add the unchanged question and send it to any model.

The kinds of links

TEMPORALLY_FOLLOWSThis message came right after that one.
ANSWERSThis reply answers that question.
MENTIONSBoth messages talk about the same named thing.
UPDATESThis decision replaces an earlier one. Gemma finds these; the pattern extractor found none in our test.
Where to use it

Anywhere history is long, things change, and space is tight

Long-running assistants

Remember what was decided months ago and why it changed.

Coding agents

Connect a bug, its cause, the file, and the fix across hours of work.

Small or local models

Models with small context windows, or a tight token budget, get only what matters.

Support bots

Keep the problem, the workaround, and the final fix together.

Team decision logs

“What did we agree on, and why?” across reversed and re-made decisions.

Not a good fit

Looking up one fact in documentation, or short chats where everything fits anyway. Ordinary search does as well there.

Guide

Add RALC to your own chatbot

1Install

Requires Python 3.10 or newer.

git clone https://github.com/Vivek0x6b/Ralc.git
cd Ralc
pip install -e ".[embed,tokens]"     # add ,gemma to use Gemma

2Create a context manager

The storage file keeps the graph between runs.

from ralc import ContextManager

ralc = ContextManager(storage="memory.db")

3Save every message as your chatbot runs

Add one line wherever your program sends or receives a message. RALC links each new message to the history automatically.

ralc.add_message(role="user", content=user_message)
ralc.add_message(role="assistant", content=reply)
ralc.save()

4Get the best context for a question

Pick a token budget that fits your model and your costs.

result = ralc.retrieve(query=question, token_budget=1000)

result.token_count      # tokens actually used (never above the budget)
result.nodes            # the chosen messages, in conversation order
result.metadata         # what happened: candidates, nodes explored, skips

5Send it to any model

The question goes in unchanged. Use whichever model you like.

prompt = result.to_text() + "\n\n" + question
# send prompt to Gemma, GPT, Claude, Llama, a local Ollama model...

6Optional: let Gemma build the links

Set GEMINI_API_KEY in your environment, then pass the Gemma extractor. Without it, RALC uses the free pattern extractor.

from ralc.extraction import GemmaExtractor

ralc = ContextManager(storage="memory.db",
                      extractor=GemmaExtractor(model="gemma-4-26b-a4b-it"))

Your chat history stays on your machine. Only the messages RALC selects are sent to the model, and with Gemma enabled, each message is sent once to Gemma to find links.

Limits

  • Tested on one synthetic conversation with 14 to 17 questions and one Gemma model.
  • We measured which messages were selected, not yet whether the model's answers improved.
  • Linking decisions by topic did not work in our test, and is not included.
  • Not built yet: importing exported chat files, an MCP server, agent integrations.
